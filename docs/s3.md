# Using a private S3 repository

Real S3 acceptance has not been run yet. The adapter uses AWS SDK for C++ 1.11.900
from the pinned vcpkg baseline. Actual SDK requests are exercised against a local
HTTPS fixture with certificate verification enabled, including retries, checksums,
conditional writes, and lost responses. Offline tests cannot prove IAM or real S3
behavior.

Create the bucket separately, block all public access, and enable default SSE-S3
encryption. Use a dedicated prefix and synthetic files for the first test. This
application requests SSE-S3 (`AES256`) on writes and never grants public ACLs.
It cannot create a bucket or remove objects.

Configure a local profile or temporary credentials outside this repository using
the [SDK credential chain](https://docs.aws.amazon.com/sdk-for-cpp/latest/api/aws-cpp-sdk-core/html/md_docs_2_credentials___providers.html).
If using a container, mount only the needed AWS profile files read-only. Do not
put keys in a Dockerfile, command arguments, environment files committed to Git,
snapshot metadata, or benchmark output. SSO requires a valid local login/cache.

```sh
export AWS_PROFILE=backup-test
backupctl init --state /work/state --bucket YOUR_PRIVATE_BUCKET \
  --prefix backupctl/test --region ca-central-1
backupctl backup --state /work/state --source /work/input
backupctl list --state /work/state
backupctl verify --state /work/state --snapshot SNAPSHOT_ID
```

To exercise recovery without the original database, run `init` with the same
bucket/prefix/region and a new empty state directory, then `restore` a listed ID.
The existing `repo.json` is validated and reused.

## Repeatable acceptance

The bounded acceptance script generates about 16 MiB of source files. It selects
a new `acceptance-<uuid>` child under the supplied test prefix and checks first,
unchanged, incremental, and old-version backups, listing, verification, and restore
with a fresh state database. It compares hashes, modes, and nanosecond timestamps.
The script leaves remote objects in that child prefix and saves its exact name,
binary hash, request counters, snapshots, and results in the new work directory.

```sh
python3 scripts/s3_acceptance.py build/release/backupctl \
  --work out/s3-acceptance --bucket YOUR_PRIVATE_BUCKET \
  --prefix backupctl/test --region ca-central-1 --profile backup-test
```

Add `--read-profile backup-restore-only` to exercise an existing restore-only role.
With a test-enabled build, `--test-crash` also terminates after the durable inventory
and resumes the same job. It does not simulate a cloud outage or credential renewal.
Credentials and IAM roles must already exist; this script does not create cloud
accounts, buckets, or policies. The offline CI invocation uses `--local-store` and
labels the result `local-harness-check`; it is not real S3 evidence.

## Prefix policy

Replace `YOUR_PRIVATE_BUCKET` and `backupctl/test` before attaching this policy to
a dedicated test role. Keep bucket management in a separate administrative role.
No wildcard action, bucket creation, or delete permission is needed.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::YOUR_PRIVATE_BUCKET",
      "Condition": {
        "StringLike": { "s3:prefix": ["backupctl/test", "backupctl/test/*"] }
      }
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::YOUR_PRIVATE_BUCKET/backupctl/test/*"
    }
  ]
}
```

A restore-only role needs `ListBucket` for listing and `GetObject` for reading.
It can use an existing configured state without initialization. `init` also works
with read-only remote access when a compatible `repo.json` already exists.

The adapter uses TLS verification, SHA-256 checksums for encoded PUT and GET bytes,
and `If-None-Match: *` for every PUT. It sets three total SDK attempts, a 3-second
connect timeout, and a 30-second HTTP deadline per attempt. There is no scheduler
retry loop. Credential discovery can add its own time before HTTP; an operation's
HTTP budget is at most roughly 90 seconds plus bounded backoff. Requests and SDK
attempts are reported separately; these are not packet-level traffic measurements.
Connections are capped at eight and the SDK executor at two threads.

Record the test prefix, request counts, object count, and stored bytes. Clean up the
test prefix separately with an administrative role after keeping any needed evidence.
Do not expire `chunks/` automatically: older snapshots may still reference them.
Set an AWS budget alert if needed; it is not a hard spending cap.

References: [conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html),
[S3 checksums](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html),
[SDK CMake integration](https://docs.aws.amazon.com/sdk-for-cpp/v1/developer-guide/build-cmake.html).
